Docker follow-up diagnostics and volume backup/restore (2026-11-04)

Port occupancy check on macOS
$ lsof -nP -iTCP:8080 -sTCP:LISTEN
COMMAND   PID          USER          FD   TYPE             DEVICE SIZE/OFF NODE NAME
com.docke 30546        piotrjodlowski 71u IPv6 ...                     TCP *:8080 (LISTEN)

$ lsof -nP -iTCP:8081 -sTCP:LISTEN
no listener

$ docker ps --filter publish=8080 --format '{{.Names}} {{.Ports}}'
workstation-web-8080 0.0.0.0:8080->80/tcp, [::]:8080->80/tcp

$ docker volume inspect workstation-mission-data --format '{{.Name}} {{.Driver}}'
workstation-mission-data local

If a desired host port is busy, inspect the PID with `ps -p <PID> -o pid=,comm=` and check Docker's published port list. Stop only a container or application you recognize and own; for Docker use `docker stop <container-name>`. If the listener belongs to another/unknown app, leave it alone and choose an unused host port, for example `-p 8082:80`.

Named volume backup
$ docker run --rm -v workstation-mission-data:/source:ro -v "$PWD/evidence:/backup" alpine:3.20 sh -c 'tar czf /backup/workstation-mission-data.tar.gz -C /source .'
[exit 0]

Restore into a disposable verification volume
$ docker volume create workstation-mission-restore-check
workstation-mission-restore-check
$ docker run --rm -v workstation-mission-restore-check:/restore -v "$PWD/evidence:/backup:ro" alpine:3.20 sh -c 'tar xzf /backup/workstation-mission-data.tar.gz -C /restore && cat /restore/check.txt'
persistent-data
$ docker volume rm workstation-mission-restore-check
workstation-mission-restore-check

The archive is included as workstation-mission-data.tar.gz. Docker Desktop stores named volume data inside its managed Linux VM; use Docker volume commands or a temporary helper container to inspect/backup it rather than relying on a fixed host filesystem path. Keep backup archives in a protected location if real application data is used.
